# Выбор ASR-модели при загрузке лекций

При добавлении лекции (раздел **«Добавить»** / Ingest) можно выбрать модель
распознавания речи (ASR) — выпадающий список «Модель распознавания» в обеих
формах (YouTube и загрузка файла). Под списком показывается подсказка «когда
какую использовать», объём VRAM и поддержка ru-en code-switching.

Этот документ — про **прикладной выбор**: какую модель брать под конкретную
лекцию. Технический ресёрч (почему именно эти 5, что отвергли) — в
[asr_backends.md](asr_backends.md).

---

## Когда какую модель использовать

Все модели заточены под основную задачу проекта — **лекции по ML/DL/RecSys на
русском с английскими терминами** («attention», «embedding», «LightGBM»). Чем
лучше модель держит code-switching (CS), тем меньше англицизмов превратится в
кириллицу («эттеншн», «эмбеддинг»).

| Модель | VRAM | Code-switching | Скорость / прогрев | Когда брать |
|---|:---:|---|---|---|
| **Qwen3-ASR 1.7B** ★ | ~4 ГБ | нативно | средняя | **По умолчанию.** Лучший баланс качества и ресурсов для лекций с англицизмами. |
| **Whisper large-v3 turbo** | ~2 ГБ | через initial_prompt | быстрая, прогрев ~1 мин | Когда нужна скорость, а англицизмов мало. Самый лёгкий старт. |
| **VibeVoice-ASR (4-bit)** | ~6 ГБ | нативно + hotwords + диаризация | медленная, прогрев до ~30 мин | Максимальное качество длинных лекций (до 60 мин одним проходом), несколько спикеров, глоссарий терминов. |
| **Parakeet-TDT 0.6B v3** | ~2 ГБ | нет (только ru) | быстрая | Лекции без англицизмов или как контрольная точка для сравнения. Английские термины запишет кириллицей. |
| **Phi-4 Multimodal (NVFP4)** | ~4 ГБ | через промпт | — | **Сейчас недоступна** (сломан путь в trtllm-serve 1.2.0rc6). В списке — серой. |

**Короткое правило:**
- Не уверены — оставьте **Qwen3-ASR** (выбор по умолчанию).
- Лекция длинная / несколько спикеров / важна точность терминов — **VibeVoice**.
- Нужно быстро прогнать много коротких записей почти без англицизмов — **Whisper**.
- Чисто русская речь без терминов / нужен baseline для сравнения — **Parakeet**.

## Как это работает под одной видеокартой

На демо-стенде одна GPU (16 ГБ), и все ASR-бэкенды делят один порт и сетевой
алиас `asr` — **одновременно работает только одна модель**. Поэтому выбор
модели реализован как **авто-свап контейнеров**:

1. Вы выбираете модель и запускаете загрузку.
2. Если выбранная модель уже поднята — транскрипция стартует сразу.
3. Если нет — API гасит текущий контейнер и поднимает нужный, ждёт готовности,
   и только потом транскрибирует. В статусе задания видно: «переключаюсь на …»,
   «прогрев … (осталось ~Ns)».

Из-за этого:

- **Первый запуск другой модели занимает время** (от ~1 мин у Whisper до ~30 мин
  у VibeVoice при холодном старте). UI предупреждает значком ⚠, когда выбор
  приведёт к свапу.
- **Параллельные загрузки выстраиваются в очередь.** Пока одна лекция
  транскрибируется, вторая (особенно с другой моделью) ждёт — это защищает GPU
  от перегрузки и не даёт «выдернуть» модель из-под текущего задания. В статусе
  ждущего задания видно «ожидание очереди: GPU занята…».
- **Нет ограничения частоты свапов на пользователя.** Тот, кто чередует тяжёлые
  модели, может надолго занять очередь — поэтому авто-свап и рассчитан только на
  доверенный круг с аккаунтами, выданными вручную (открытой регистрации нет).

По умолчанию в списке предвыбрана та модель, что **сейчас поднята** — чтобы
случайно не запустить долгий свап. Тяжёлую модель выбираете осознанно.

## Включение авто-свапа на GPU-боксе

Авто-свап выключен по умолчанию (`ASR_AUTOSWAP_ENABLED=false`): на дев-машине
без Docker/GPU выбор модели просто валидируется, а транскрипция идёт на тот
бэкенд, что поднят. Чтобы API мог сам переключать контейнеры, ему нужен доступ к
docker-сокету — это включается отдельным overlay-файлом
[`docker-compose.autoswap.yml`](../docker-compose.autoswap.yml).

> ⚠ **Безопасность.** Доступ к `/var/run/docker.sock` = root на хосте. Включайте
> только на доверенной GPU-машине (сайт за логином, аккаунты выдаются вручную).
> Менеджер дёргает только `start`/`stop`/`ps`/`inspect` и только над
> контейнерами из белого списка `asr-*`.

Порядок:

1. **Создать (не запуская) контейнеры всех нужных моделей** — один раз:
   ```bash
   docker compose --profile asr-whisper --profile asr-qwen3 \
     --profile asr-parakeet --profile asr-vibevoice create
   ```
   После этого `docker start <container>` поднимает их быстро (веса в кеше).
   Если контейнер не создан, при выборе модели задание упадёт с понятной
   ошибкой «контейнер создан? …».

2. **Узнать GID docker-сокета:**
   ```bash
   stat -c '%g' /var/run/docker.sock     # обычно 999 или 998
   ```

3. **Прописать в `.env`:**
   ```env
   ASR_AUTOSWAP_ENABLED=true
   DOCKER_GID=<gid из шага 2>
   ```

4. **Поднять стек с overlay:**
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.autoswap.yml \
     --profile full up -d
   ```

Проверка: `GET /asr-models` (или открыть форму «Добавить») вернёт `autoswap: true`
и `active` = ключ поднятой модели.

## API

`GET /asr-models` (требует авторизации) — каталог для фронта:

```json
{
  "models": [
    {"key": "qwen3", "label": "Qwen3-ASR 1.7B", "vram_gb": 4.0,
     "code_switch": "нативно", "when": "…", "available": true, "recommended": true},
    ...
  ],
  "default": "whisper",
  "active": "qwen3",
  "autoswap": true
}
```

Выбор передаётся полем `asr_model` (ключ модели) в `POST /ingest` (JSON) и как
query-параметр в `POST /ingest-upload`. Неизвестный или недоступный ключ → 400.
