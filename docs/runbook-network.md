# Сетевой рунбук: двойной NAT + WireGuard

> **Это РУЧНАЯ настройка на реальном оборудовании.** Автоматизации нет — все шаги
> выполняются вами в веб-интерфейсах роутеров и в PowerShell на ПК. Значения
> IP-адресов в примерах — плейсхолдеры; подставьте свои.

Сокращения:
- **R1** — входной (внешний) роутер, WAN = белый IP провайдера.
- **R2** — второй роутер (или Wi-Fi-точка), WAN подключена к LAN R1.
- **PC** — ваш GPU-компьютер.

---

## Рекомендация: объедините двойной NAT в одинарный

Если R2 поддерживает режим **bridge / AP / modem mode** — переведите его туда.
Тогда PC окажется напрямую за R1, проброс выполняется однократно,
NAT-hairpin работает проще, и вся отладка упрощается вдвое.

Двойной NAT (правила на двух роутерах) — запасной вариант, если перевести R2 в
bridge невозможно.

---

## STEP 0 — проверить, что IP не CGNAT

На ПК выполните:

```powershell
(Invoke-WebRequest https://api.ipify.org).Content
```

Откройте веб-интерфейс R1 → страницу WAN-статуса. WAN IP на роутере **обязан
совпадать** с тем, что вернула команда.

Если адреса различаются **или** WAN-IP роутера попадает в диапазон `100.64.0.0/10`
— вы за CGNAT. Провайдер не выдал вам настоящий публичный IP: ни сайт, ни
WireGuard входящим трафиком работать не будут. Решение — запросить у провайдера
статический белый IP (обычно платная опция).

Этот шаг — жёсткое предусловие для всего остального.

---

## STEP 1 — статические LAN-адреса

Порядок важен: сначала фиксируем адреса, потом прописываем проброс.

### 1a. R1: зарезервировать адрес для R2

В веб-интерфейсе R1 найдите **DHCP → Static leases / Address reservation**.
Добавьте запись:

| MAC-адрес | Выдаваемый IP | Комментарий |
|-----------|---------------|-------------|
| MAC WAN-порта R2 | `192.168.0.2` | R2 WAN fixed |

MAC WAN-интерфейса R2 обычно написан на корпусе или виден в списке клиентов R1.

### 1b. R2: зарезервировать адрес для PC

В веб-интерфейсе R2 → **DHCP → Static leases**:

| MAC-адрес | Выдаваемый IP | Комментарий |
|-----------|---------------|-------------|
| MAC сетевой карты PC | `192.168.1.10` | PC fixed |

MAC сетевой карты PC:
```powershell
Get-NetAdapter | Select-Object Name, MacAddress
```

> R1 и R2 обязаны работать в **разных подсетях**: например `192.168.0.0/24` (R1)
> и `192.168.1.0/24` (R2). Одинаковые подсети ломают маршрутизацию.

После изменений перезагрузите R1 и R2 и убедитесь, что PC получил `192.168.1.10`.

## STEP 2 — таблица проброса портов (два хопа)

Настраивается на **обоих** роутерах. Протокол сохраняется на каждом хопе.

### Правила на R1 (WAN = белый IP → R2 WAN)

| Имя | Внешний порт | Протокол | Назначение |
|-----|-------------|----------|-----------|
| http-acme | 80 | TCP | `192.168.0.2:80` |
| https-site | 443 | TCP | `192.168.0.2:443` |
| wireguard | 51820 | **UDP** | `192.168.0.2:51820` |

### Правила на R2 (WAN = `192.168.0.2` → PC LAN)

| Имя | Внешний порт | Протокол | Назначение |
|-----|-------------|----------|-----------|
| http-acme | 80 | TCP | `192.168.1.10:80` |
| https-site | 443 | TCP | `192.168.1.10:443` |
| wireguard | 51820 | **UDP** | `192.168.1.10:51820` |

**Типичные ошибки:**

- В R1 указан IP PC (`192.168.1.10`) вместо IP R2 WAN (`192.168.0.2`) — R1 не
  видит PC напрямую, пакет теряется.
- Использован режим **DMZ** на R1 вместо точечного проброса — DMZ открывает ВСЕ
  порты, что небезопасно; используйте только три перечисленных.
- Перепутан протокол: WireGuard — **UDP**, 80/443 — **TCP**; смешивание ломает
  оба сервиса.
- Порт 51821 (wg-easy UI) **не пробрасывайте** — он должен быть виден только
  через WireGuard-туннель или по SSH port-forward.

## STEP 3 — DNS A-запись

У вашего регистратора домена добавьте A-записи:

| Имя | Тип | Значение | TTL |
|-----|-----|----------|-----|
| `@` (apex) | A | `<белый IP R1>` | 300 |
| `www` | A | `<белый IP R1>` | 300 |

TTL 300 (5 минут) на время настройки — потом можно увеличить.

Если ваш провайдер выдаёт **динамический** IP, настройте DDNS-клиент на R1
(встроен в большинство роутеров: no-ip.com, DynDNS, или сервис вашего
провайдера) и укажите DDNS-имя в A-записи.

Проверьте распространение записи:
```powershell
Resolve-DnsName your-domain.ru -Type A
```

## STEP 4 — Windows Defender Firewall

Выполните **от имени администратора** в PowerShell:

```powershell
New-NetFirewallRule -DisplayName "nginx 80"  -Direction Inbound -Action Allow -Protocol TCP -LocalPort 80  -Profile Any
New-NetFirewallRule -DisplayName "nginx 443" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 443 -Profile Any
New-NetFirewallRule -DisplayName "wg 51820"  -Direction Inbound -Action Allow -Protocol UDP -LocalPort 51820 -Profile Any
```

Проверьте, что Docker действительно слушает на `0.0.0.0` (не `127.0.0.1`):

```powershell
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in @(80, 443) }
```

В столбце `LocalAddress` должно быть `0.0.0.0`, а не `127.0.0.1`.

## STEP 5 — тест ИЗВНЕ локальной сети

> **Обязательно тестировать с мобильного интернета (4G/5G) или с VPS —
> не из домашней сети.** Изнутри LAN результат недостоверен из-за NAT hairpin
> (см. ниже).

### TCP (сайт):

```bash
nmap -Pn -p 80,443 <белый IP>
curl -Ik https://your-domain.ru
```

Ожидаемый результат: порты открыты, `curl` возвращает HTTP 200 или redirect,
заголовок `Server:` присутствует.

### UDP (WireGuard):

Создайте клиентский профиль в wg-easy UI (доступен по `http://127.0.0.1:51821`
с ПК или через `ssh -L 51821:localhost:51821 user@pc`). Установите WireGuard на
телефон или ноутбук, импортируйте QR/конфиг и активируйте туннель.

Успешный признак: в wg-easy UI у клиента появляется ненулевое значение
`Last handshake` (обновляется в течение ~30 с после подключения).

### Бисекция при проблемах:

С ноутбука **в LAN R1** (но не через R2):
```bash
nmap -Pn -p 80,443 192.168.0.2
```
- Открыто → проблема между R2 и PC (правила R2 или файервол PC).
- Закрыто → проблема на R1 или провайдере.

## NAT hairpin (петля внутри LAN)

Находясь **внутри** домашней сети, браузер часто не может открыть `https://your-domain.ru`,
потому что DNS разрешает домен в белый IP, а роутер не умеет «развернуть»
соединение обратно внутрь (NAT loopback / hairpin NAT).

**Варианты решения:**

1. Включить **NAT Loopback** на R1 и R2 (если поддерживается прошивкой —
   обычно называется «NAT Loopback», «Hairpin NAT» или «Loopback NAT»).

2. Добавить запись в `C:\Windows\System32\drivers\etc\hosts` на ПК:
   ```
   192.168.1.10  your-domain.ru
   ```
   Это работает только для ПК, не для других устройств в LAN.

3. Настроить **split-horizon DNS** на R2 (если прошивка поддерживает локальный
   DNS-сервер) — домен резолвится в `192.168.1.10` изнутри LAN.

Единственный достоверный тест доступности сайта из интернета — с мобильного
или внешнего VPS.
